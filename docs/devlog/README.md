# Devlog — daily progress reports

## Schedule

Full write-ups are dropped at **07:00 UTC+8** (Hong Kong / Taipei / Singapore / Kuala Lumpur).

## Filename convention

```
docs/devlog/YYYY-MM-DD-0700-hkt.md
```

The date is the **calendar day in UTC+8** when the report is published (not necessarily when work ended).

## What each report contains

1. **Summary** — one paragraph on what shipped
2. **Commits / PRs** — what landed on `main`
3. **Architecture** — key files and how they connect
4. **Tests & build** — pass/fail counts
5. **How to use** — user-facing steps for new features
6. **Next** — next PR(s) in the DAG, no pause for approval

## Autopilot rule

The agent **always moves on** to the next PR in the design DAG unless blocked. Standing instruction — no need to ask “do next?”

## Automation note

Reports are written when an agent session runs. For a true 07:00 HKT drop without opening Cursor:

1. **Cron + reminder** — `0 7 * * * TZ=Asia/Taipei` runs `scripts/daily-devlog-reminder.sh` (creates a stub if missing).
2. **Cursor / cloud agent** — schedule a daily task at 07:00 HKT with: *“Write yesterday’s devlog to `docs/devlog/YYYY-MM-DD-0700-hkt.md` and continue the next PR.”*
3. **Manual** — open the latest `docs/devlog/*-0700-hkt.md` anytime.

AI prose cannot be generated by git-only cron; something must invoke the agent.
